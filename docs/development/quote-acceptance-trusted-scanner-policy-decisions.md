# B6.2 policy/contract decision proposal

Status: APPROVED_WITH_USER_AMENDMENTS, 2026-10-26. User explicitly authorizes narrow public contracts and whole-artifact content-read capability for B6.2. Existing B6.2 task authorizes independent runtime discovery, scanner/parser implementation, fail-closed engineering and tests. No default capability grants; content release must satisfy the approved rules below. Quotes remains sole owner; B5 bytes and B6.1 Proof/Content/Case binding rows stay immutable.

## Proposed package A

1. Whole-artifact permission: add `quotes.readAcceptanceProofContent`, explicit custom-role assignment only, no Owner/default grants. Requires quotes.read + quotes.readAcceptanceEvidence + current record/FLS/B5 Buyer scope. This capability authorizes the entire uploaded artifact, which may contain unstructured PII; it is not per-field redaction or PII discovery. Existing readAcceptanceEvidence remains metadata-only. Grant only to a separately scoped synthetic reviewer through official AccessControl provisioning for Connected tests.
2. New narrow GET operations: `getQuoteAcceptanceProofScanHistory` at existing proof route + `/scans` (bounded metadata) and `downloadQuoteAcceptanceProofContent` at + `/content` (attachment only). Extend existing security/metadata responses with effective server scan state. No user endpoint accepts verdict/lease/scan results. No public Retry Scan command in this package; bounded background retries and Development-only fault probes suffice.
3. Backend policy, exact Workspace Enabled + Version required; effective digest binds every limit/parser/runtime pin. Only explicitly configured synthetic Workspaces enabled in Development. CLEAN is technical, not authenticity/authority/VERIFIED/acceptance.
4. Conservative PDF policy: reject encryption/passwords, parser repair/warnings, scripts/actions, forms/XFA, embedded files, external files/URI links, multimedia/dynamic content, unsupported filters/features and incomplete parser output. Parse full bounded qpdf v2 graph, not lexical string matching. No rewrite/sanitization of original proof. Initial supported subset is static text/vector PDFs; inline images, image/Form/Pattern/Shading execution, XML metadata and unimplemented rendering constructs are explicitly blocked rather than declared safe. Both object graph and decoded content operators are checked. Initial limits: 10 MiB input,100 pages,10000 objects,64 JSON/object nesting,32 MiB decoded stream/output envelope; native validator process bounded to512 MiB and15 seconds. Unsupported structure remains INVALID_PDF/indeterminate, never CLEAN. These are versioned initial technical limits, not permanent business rules.
5. Real ClamAV, allowlisted absolute runtime and hash manifest, process/loopback-only daemon; actual engine VERSION and official signed signature DB provenance. Initial signature maximum age24 hours, future timestamp refused, before/after DB version must agree. Supported/pinned versions come from verified distribution metadata. Configure exceed/partial limits as alert/failure. Malware scan deadline30 seconds; no scanner/signature authority => no CLEAN.
6. Small scoped worker over existing BackgroundService/DI infrastructure. SQL lease90 seconds, work deadline45 seconds, maximum2 concurrent scans/process. Attempt identity and lease CAS; stale lease cannot commit. Initial max3 automatic attempts per policy/signature epoch, backoff30 seconds then2 minutes; max12 lifetime automatic attempts/proof. Exhaustion is sticky NEEDS_INTERVENTION: submit a new proof; no policy edit or counter-reset endpoint can reset an exhausted job. Scan calls outside SQL transactions. Worker off by default.
7. Immutable append-only ScanAttempts/results plus separate mutable owner ScanJob/lease state. Commit terminal result/state/audit/outbox atomically. Cancel/restart leaves lease to expire; recovery appends explicit expired attempt outcome, no invented CLEAN. Old proof bytes/metadata not overwritten. Previously CLEAN becomes non-reviewable when current policy/runtime/signature freshness no longer matches; old verdict history remains unchanged. No effect on historical ACCEPTED lifecycle.
8. Content release only if current effective CLEAN has both structural PASS and real malware CLEAN, matching bytes/hash/size/lease/policy and current fresh trusted runtime signature. Attachments use private,no-store/nosniff and sandbox CSP; no automatic inline viewer or raw SQL reference. Download recomputes hash, bounded10 MiB. Wrong permission/Workspace/FLS or pending/unsafe/stale/failed => blocked. No VERIFIED/ACCEPTED/Won.
9. Proof and commercial scan evidence remain technically indefinite and immutable; no audit DELETE/retention-law claim. Lifetime attempt cap bounds automatic commercial scan-history growth. Operational health/queue counters are bounded aggregates, no raw file contents/log diagnostics. A legal retention/deletion schedule remains a separate policy, consistent with B6.1.
10. Development setup: official portable binaries in task-local runtime, signature/integrity/license evidence; no Windows service, global PATH, admin changes, Docker Desktop startup or unknown binaries. Same-user bounded native processes are not a hardened OS sandbox; production requires a dedicated low-privilege/isolation deployment and validation. If a trusted runtime cannot be provisioned, report PARTIAL/BLOCKED, never emulate real acceptance.

## Binding user amendments — approved 2026-10-26

- Metadata and bounded Scan History require existing read/read-evidence authority and remain readable for pending/unsafe/failed/exhausted proofs. CLEAN is never a prerequisite for failure history. No bytes/storage references/raw diagnostics in history.
- Content separately requires quotes.readAcceptanceProofContent plus Quote/Case/Workspace/record/FLS/source authority and current effective CLEAN bound to immutable stored SHA, current policy and live fresh trusted engine/signatures. Attachment-only, private/no-store/nosniff/sandbox headers.
- Default maximum3 automatic attempts per epoch and12 lifetime attempts; exhaustion becomes NEEDS_INTERVENTION with a reason. Recovery is expired-lease append-only failure + bounded retry; exhausted cases require a NEW proof (different evidence bytes), not a counter-reset command. No manual override or automatic UNSAFE-to-CLEAN metadata edit.
- Effective epoch binds policy digest, parser/runtime pins and actual signature version. Policy or trusted runtime/signature epoch changes invalidate release until a new complete successful scan. Stale/unavailable/unverified runtime blocks release without rewriting historical results. Historical acceptance remains untouched.
- Implement SQL worker/leases/append-only results, new narrow history/content contracts and explicit synthetic content-reader provisioning within B6.2; no B6.3+ scope. All negative/positive acceptance must use real scanner and real API/SQL/browser where claimed.
- Live runtime authority also performs a bounded two-second VERSION probe bound to the pinned engine and signed daily database version. A hung listener is unavailable, including for release of previously CLEAN content.
