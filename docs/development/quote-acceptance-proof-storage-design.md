# B6.1 — Acceptance Proof Storage & Quarantine

Status: user-authorized implementation. The new task supersedes B6's blanket storage block while scanner is absent: valid uploads may persist QUARANTINED, with no release or verification.

Quotes owns separate AcceptanceCases/AcceptanceProofs/AcceptanceProofContents. Reuse QuotesDbContext, canonical Quote lock, command receipts/audit/outbox, B5 immutable source binding and current source FLS. Case/proof have independent versions; never increment QuoteRV merely for evidence collection. Case binds exact B5 document/root/revision/commercial hash/PDF hash/Buyer. A redundant B5 document alternate key is permitted solely to enforce composite Case→Quote+Document SQL integrity; no B5 rows/bytes change.

Create/upload require quotes.submitAcceptanceEvidence + quotes.readAcceptanceEvidence + quotes.read, exact record/source FLS. Metadata read uses readAcceptanceEvidence+read. No automatic/default grants, no verify/accept rights implied. Scope current unarchived/date-valid SENT and current B1/document binding; linked GateC and verification amount limits do not prevent quarantined collection. Retained historical metadata stays readable by current authorization.

Raw PDF upload uses declared application/pdf binary contract and bounded encoded filename/evidence-type headers. Authorize before reading; four in-flight upload slots,10MiB hard maximum/file,5files and25MiB/case,256MiB/250proofs/100cases per Workspace defaults, exact Workspace versioned configurable policy. Stream/hash with a15sec read deadline outside SQL locks. Signature/version/EOF candidacy only; no parse/render/decompress. B6.2 owns page count/encryption/active-content/malware verdict; no fake CLEAN/page count.

Lock order idempotency scope → Workspace quota → Quote aggregate → Case. Reauthorize/reload after streaming. Authorized same-key replay compares server-computed hash/size/sanitized metadata/expectedVersion and precedes stale-case/quota/new-upload eligibility checks. Same-case content hash uniqueness; no cross-Workspace dedup. Atomic encrypted bytes+metadata+CaseRV+quarantine+receipt+audit/outbox. Only Case version changes. No deletion/overwrite/retargeting.

Ciphertext stored using ASP.NET Data Protection purpose per Workspace/Case/Proof; plaintext SHA/size retained. Local SQL TDE is off. Windows profile key persistence/DPAPI is a Development control, verified across restart; production key custody, encryption and coordinated database/key backup/restore must be separately verified. No credentials or key material in evidence. No public content endpoint. Metadata queries never read ciphertext. No scanner adapter/access/release is registered in B6.1.

Case initially COLLECTING_PROOFS; uploads set Case QUARANTINED, Proof StorageStatus QUARANTINED and ScanStatus SCAN_PENDING. Immutable Proof/Content; future scan events append independently in B6.2. Scanner interface accepts trusted server content/hash and emits source/version/timestamps/verdict, not client flags; unavailable never clean. No fabricated scan result rows.

B6.2 plan: ClamAV + isolated structural validator, trusted local network/Unix socket, streamed bounded bytes, enforced StreamMaxLength, freshclam/versioned signatures, timeout/cancellation/resource/concurrency bounds, engine/hash correlated immutable verdicts; unsafe/timeout/unavailable remain quarantined. No executable/service/container installation in B6.1. ClamAV is not on PATH; Docker CLI exists but no deployment or service is inferred.
