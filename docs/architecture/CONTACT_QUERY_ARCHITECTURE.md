# Contact list and Tasks follow-up query

Current implementation, 2026-10-07. The approved remediation replaces the original unbounded Contact list. HTTP contract generation is owned by the parent contract work; the source behavior below is verified independently of that generation.

## Query boundary

`GET /contacts` returns `items`, `pageInfo` (`hasNextPage`, `nextCursor`, `totalCount`), and `followUpAvailable`. The default limit is 25; accepted limits are 1–100. Persistence fetches at most limit + 1 rows to identify continuation, then the handler returns at most limit rows. `GET /contacts/summary` independently aggregates total and status counts from the same authorized, filtered SQL relation; it does not derive global counts from a page.

Supported query parameters are cursor, limit, search, status, ownerId, ownerScope=my, source, relationshipLevel, decisionRole, doNotContact, link=linked/unlinked, sort, nextFollowUpDate, and followUp=today/overdue. Unsupported or repeated parameters fail validation. The default excludes archived Contacts; explicit status=archived selects the preserved archived lifecycle. Link predicates use active Contacts-owned CustomerRelationships, correlated by workspace and Contact ID; they do not read Customer persistence or expose a Customer display value.

Search uses fullName plus readable displayName, workEmail, personalEmail, mobilePhone, workPhone, and otherPhone. JSON profile predicates execute through parameterized SQL Server JSON_VALUE; Contact rows are deserialized only after bounded paging. Optional hidden/masked fields cannot participate in search. Filtering by a withheld ownerId, source, relationshipLevel, decisionRole or doNotContact is refused. Required-field restrictions refuse the Contact read through canonical ContactAuthorization.

## Authorization and cursor

Authenticated active workspace membership and contacts.read are resolved through ContactAuthorization and canonical AccessControl. Trusted WorkspaceId and OWN owner-member predicates are applied before count, aggregate, ordering and paging. ownerScope=my resolves the trusted member on the server. TEAM/CUSTOM remain fail-closed. Each ordinary enriched list authorizes contacts.read once and tasks.read once, with no per-Contact record authorization loop.

The data-protected cursor carries position and expiry and binds to workspace, authenticated member, effective owner predicate, normalized filters, readable search fields, Task assignee scope, follow-up availability, and business-date boundaries. Expiry is one hour. Malformed, expired or mismatched cursors fail validation. Orders are updatedAt DESC/ContactId DESC, fullName ASC/ContactId ASC, or nextFollowUpAt ASC NULLS LAST/ContactId ASC. SQL uses a null predicate for SQL Server-compatible null-last ordering. Count is computed before continuation predicates. Count and page are separate database commands; this implementation does not claim a transactionally frozen collection during concurrent writes.

## Tasks-owned projection

Tasks creates `tasks.ContactFollowUpReadProjection`. Its keyless public model is `UnicoreCRM.Operations.Tasks.Contracts.ContactFollowUpProjectionRow`, with WorkspaceId, ContactId, AssigneeId and MinDueAt. The view groups the authoritative Tasks table by workspace, Contact target and assignee. Eligibility is Status=Open (stored enum 0), ArchivedAt IS NULL, RecordModuleKey=contacts, and a non-null/nonempty RecordId. RelationshipRef alone does not target a Contact. The current model has no follow-up Task type, so no extra type rule is invented. Completed, cancelled and archived Tasks never contribute.

Contacts maps this contract with HasNoKey/ToView; its migration snapshot records the mapping and does not create or alter Tasks persistence. Tasks migration `20261006150000_ContactFollowUpReadProjection` alone owns the view. Contacts requires `IContactFollowUpReadAuthorityResolver.ResolveAsync` per request, implemented through actual TaskAuthorization/tasks.read. Required readable Task fields are recordRef, dueAt, assigneeId, status and archivedAt. Withheld/masked or missing required field decisions, denied capability, invalid workspace and unsupported scope yield unavailable authority. READ_ONLY values remain readable. Full Task representation authorization can conservatively refuse other required-field restrictions as well.

`ContactFollowUpReadAuthority.Compose(view)` applies its trusted workspace and, for OWN, its canonical scope assignee before taking the final minimum across assignee rows. The result model is ContactNextFollowUp (WorkspaceId, ContactId, NextFollowUpAt). The Contacts SQL join uses both WorkspaceId and ContactId and independently retains Contact authorization. A left join yields null when no authorized eligible Task exists. The SQL view itself has no caller authorization and must never be joined without resolver-issued authority.

Contact FLS on nextFollowUpAt also gates projection availability. Ordinary Contact paging continues with followUpAvailable=false when follow-up is unavailable; explicit follow-up sort/filter requests fail ACCESS_DENIED rather than returning an empty successful result or another sort. A mismatched Task/Contact trusted workspace is refused. No mutable next-follow-up value is duplicated on Contact. Today/date filters use the workspace timezone through IWorkspaceTimeZoneReader and half-open UTC day bounds; overdue means earlier than that business-day start. Missing/invalid timezone refuses the date-dependent feature.

## Activity security decision

TaskActivity record-scope and field-security semantics remain AUTHORITY_GAP. Existing TaskActivitySecurity is unchanged: Activities are reachable only for WORKSPACE Tasks scope with no restrictive Tasks field policy. listActivities returns an empty page when unreachable; logActivity refuses ACCESS_DENIED. This is conservative reachability, not a claim that Tasks FLS is Activity FLS. ActorId is not an Activity owner, and Contact ownership does not grant Activity access.

Contact lastContactedAt is conceptually Activity-derived but unavailable in connected mode until Activity scope and field-security authority is explicitly defined. No Contact Activity projection, Activity query, lastContacted filter or sort is added. Reserved future communication semantics are latest authorized occurredAt for Call, Email, Meeting or Message; Note and System are excluded. That reserved meaning does not authorize disclosure. The optional Activity blocker does not block Contact paging or Tasks-derived nextFollowUpAt.

## Indexes and validation

Contacts migration `20261006144337_ContactListReadProjectionIndexes` creates only nonunique indexes (WorkspaceId, UpdatedAt, ContactId) and (WorkspaceId, FullName, ContactId). The timestamp index supports reverse scans within a workspace for the descending order. FullName is nvarchar(200); workspace and Contact IDs are nvarchar(128). Their declared 912-byte name-index key fits SQL Server's 1700-byte nonclustered key limit. Existing owner/creation and relationship indexes remain. These indexes do not claim to cover every JSON filter or prove a measured query-plan/throughput target.

Structural performance evidence is bounded page materialization, server filters/sorts/counts/summary, one set-based Tasks view join, and constant owner authorization calls. There is no per-Contact Task or Deal query and no Activity access path. JSON substring search and authorized aggregates can still scan many rows. 10K concurrent-load proof is NOT_ESTABLISHED.

Focused executable verifiers are `scripts/ContactFollowUpVerifier`, `scripts/LeadKanbanVerifier`, `scripts/verify-contacts-read-core.ps1`, and `scripts/verify-access-control-record-access.ps1`. Execution logs are local review artifacts rather than production source. The migration verifier upgrades an existing Contact, verifies index existence/key order and ownership, rolls back/reapplies, runs the clean Contacts chain, installs the Tasks-owned view separately, and checks snapshot consistency. All destructive verifier cleanup is confined to a newly allocated GUID-named disposable database. Author-session adversarial review is not a separate principal-attested independent review or release freeze.
